# Reward-source loss-path audit — 2026-07-29

## Finding

The verifier-free sweep code selected majority/random/consensus terminals only after
`_compute_per_step_rewards(text, gold)` had built every rollout's step reward from the
gold answer.

For the relevant sweeps, `use_l2a=False` and `use_contrastive=False`. The replacement
`per_rollout_terminals` were therefore used by diagnostics but never copied into
`per_rollout_step_rewards`, which are what `_compute_step_advantages(...)` and the loss
consume.

This is a control-path failure, not evidence that random reward is as effective as gold.

## Claim impact

- Gold arms remain real gold-reward runs.
- Non-gold majority/random/consensus arms using this path are mislabeled gold-reward runs
  with non-gold diagnostics.
- The prior claim that reward quality is unidentifiable because random matched gold across
  EMA/group-normalized Qwen, SmolLM2, and 7B regimes is not established by those runs.
- The prior majority-versus-random conclusion is also not established.
- Historical L2a runs predate this reward-source switch and are unaffected by this specific
  bug. Their separate label-leakage audit still stands.
- The G1 constant-terminal arm uses `reward_source=gold` and is unaffected.
- Offline `indep_cov` and RAPR scoring are separate code paths and are unaffected.

## Repair

The trainer now:

1. Computes raw label-free OMP step rewards.
2. Selects gold/majority/random/consensus terminals.
3. Rebuilds the exact per-step arrays consumed by advantage normalization from those
   selected terminals.

The regression suite sets `alpha=0` and constant spread, then proves that swapping selected
terminal vectors from `[1, 0]` to `[0, 1]` swaps the exact loss-side reward arrays.

## Second finding: trajectory advantage did not cover the trajectory

The first repaired gold run exposed another loss-path bug. With
`alpha=0`, `terminal_spread=constant`, and `step_advantage_mode=group_mean`,
the logged within-rollout token-advantage variance was nonzero.

`_build_per_token_advantages(...)` copied the trajectory scalar only into
identified step spans. Unmatched and trailing completion tokens received zero,
so this was not exact trajectory-level GRPO. The run was stopped at step 55,
before any checkpoint, and is not evidence for the repaired method.

The constant-advantage path now bypasses segmentation and applies the same scalar
to every generated token, with the completion mask applied afterward. A regression
test proves full non-padding-token coverage and exactly zero within-rollout
variance for a constant trajectory advantage.

The first clean repaired attempt later yielded correctly to unrelated GPU work at
step 194, before the original 250-step checkpoint interval. Because no checkpoint
existed, those steps were not resumable evidence for the final model. The shared-host
runner now checkpoints every 50 steps and requires two consecutive clear-capacity
checks before each attempt; subsequent preemptions resume from the latest checkpoint.

The frozen-evidence preflight then exposed an extractor mismatch shared by the core
trainer and evaluator: boxed answers such as `\boxed{\$460}` and `\boxed{460}` were
not canonicalized identically, and boxed commas bypassed `_norm_num`. Both paths now
normalize escaped currency, commas, percent signs, and single-number unit strings.
Regression cases cover these forms.
